# HopStat v2.1.91

An IPv4-only session no longer claims IPv6, and the network map reads the way it is pointed at.

## Fixes

- **A session announced a family it does not carry** — every BGP peer was configured with both IPv4 and IPv6 unicast, the unused one marked disabled. That marking has no effect over GoBGP's API: it re-enables every family it is handed and advertises a capability for each, so an IPv4-only session announced IPv6 and the router logged an NLRI mismatch against it (`peer: <inet-unicast inet6-unicast> us: <inet-unicast>`). A peer is now configured with exactly the family it carries.
- **A hovered hop was hard to tell from a hovered cable** — hops whose only route is a backup were drawn with a see-through middle, so the cables running behind them stayed visible through the box. Pointing at one of those cables read as hovering the cable while it was really hovering the box, and lit that box's route. Backup hops now carry the same fill as every other box, and cables ignore the pointer outright: only boxes select a route.

## Improvements

- **No route is drawn in alarm red** — the colour a node takes on the map is just an identity, but red reads as an outage on a network diagram. The red slot is now magenta.
