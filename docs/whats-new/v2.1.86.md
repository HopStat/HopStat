# HopStat v2.1.86

Reflected paths are recognised, so the active route matches the router in one more case.

## Fixes

- **A reflected path was treated as equal to a directly learned one** — two paths for the same prefix could tie on local preference, AS path length, origin and MED, leaving the choice to a tiebreak that had nothing to do with how the router decides. Paths now carry their originator and cluster list, which say whether the advertising router learned the path from an external peer or received it through a route reflector. Preferring the directly learned one is the "eBGP over iBGP" step of the decision process, and it is evaluated before path age — a reflected path five days old loses to a directly learned one a minute old, which is what the router does.
- **A shorter cluster list wins** when both paths were reflected, per RFC 4456.

## Notes

- Local policy still overrides all of this on the router, and the levers it uses — weight, route-map preferences, the IGP metric to the next hop — are not carried in what a neighbour advertises. Where the advertised attributes do not separate two paths, the selection is deterministic rather than authoritative.
- The admin path lookup added in v2.1.85 shows these attributes, so a disagreement can be traced to the path that carries them.
