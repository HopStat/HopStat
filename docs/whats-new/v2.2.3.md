# HopStat v2.2.3

The settings you can safely change while HopStat is running have moved out of `config.yaml` and into the admin panel.

## Moved to Admin → Settings

- **Query timeout** and **traceroute timeout** now sit alongside the other query defaults. They are read when a query starts, so a change applies to the next query rather than the next restart. Values outside 1–600 seconds are refused at the point of saving, instead of being stored and quietly ignored.
- **Self-update** is now a switch in the panel. It is read each time the updater is asked, so turning it off stops an update that would otherwise have been offered, without a restart.

Existing config files keep working: on first run the values in `config.yaml` seed the settings, and from then on the panel owns them. A value set in the panel is never overwritten by a later restart.

## What stayed in the config file, and why

Some settings cannot move without pretending to do something they don't:

- `server.host`, `port`, `mode`, `tls_cert`, `tls_key`, `autocert_domain` and `bgp.listen_port` / `listen_addresses` are used to bind sockets at startup.
- `database.path`, `security.jwt_secret` and `security.credential_key` are needed before the database can be opened or its stored credentials decrypted — which is where settings live.
- `server.trusted_proxies` and `behind_cloudflare` configure the HTTP router as it is built.
- `query.max_concurrent` sizes the worker pool at construction, and the `flood_control` limits build the rate limiters at startup.

Changing any of these still means editing `config.yaml` and restarting. The generated config now says which of its values merely seed the panel, so it is clear which ones are worth editing there.

## Fixes

- **A data race in the brute-force guard.** Its background cleanup goroutine read the cleanup interval while running, and two tests left such a goroutine alive after finishing — so a later change to that interval raced with it. The interval is now read once, on the goroutine that creates the guard, and handed to the background one. The rate limiter, the JWT deny list and the query result store carried the same shape and got the same treatment. Found by the race detector, which the release gate has run on every commit since v2.2.0.
