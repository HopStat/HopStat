# HopStat v2.2.15

A quieter release. Most of these fixes are races that a busy looking glass could
actually hit, plus two places where the answer HopStat showed you was wrong.

## Fixes

- **Query results could be read while they were being written** — the in-flight query store handed out the live result object, and a running query kept writing to it. Fetching a query's result while it was still streaming could return half-written data. The store now copies in both directions, so readers never share memory with the query goroutine.
- **Agent connections are re-checked on every connect** — an `lg_node` agent URL was validated once, when you saved it. A hostname whose DNS answer changed afterwards was still dialled. Every connection now re-resolves and re-validates the address, so the check cannot go stale between saving the URL and using it.
- **The network map could lose its selected path** — when the chosen route carried no AS path, the node reported *no* best path, or the map drew every path as a backup. Nodes now always report exactly one selected route.
- **A synthesized default route could be shown as best** — for a node with more than one default-route neighbour, a fabricated route (no RIB evidence) was sometimes flagged as the selected one. Only a route the RIB confirms is flagged best now.
- **Backup BGP routes were dropped** — the route parser discarded every path not marked with `*`, so only the best route survived. Alternate paths now appear alongside it.
- **The audit log ignored its date filter** — the admin audit page accepts a from/to range, and it was not applied. You got the whole log back regardless of the dates you picked.
- **A guessable JWT secret was accepted** — a secret made of sequential digits passed the "is this long enough" check and the entropy check. Common patterns like that are now rejected at startup.
- **A truncated GeoIP database was installed** — a `.mmdb` larger than the download cap was quietly cut short and moved into place as if it were valid. Oversized and truncated archives are now refused.
- **The broadcast address was accepted as a ping target** — `255.255.255.255` passed the blocklist, so a query naming it would have the server send a broadcast probe. It is now blocked, alongside the duplicate blocklist in the agent.
- **CPU and memory could disagree with their own severity badge** — a reading that rounded to `70%` could still be marked `ok`, while an exact `70%` was `warning`. The severity now matches the number you see.
- **The theme cache no longer throws on locked-down storage** — Safari private browsing and partitioned browser profiles raise on Web Storage access instead of returning null, which could take the page down. Reads and writes now degrade quietly, leaving the stored preference unset.
- **Outbound downloads refuse to leave their host** — the GeoIP, GitHub and Cloudflare clients followed redirects anywhere, so a compromised endpoint could bounce a request to an internal address. Same-host redirects still work; leaving the host is refused.

## Notes

- The circuit-breaker threshold on the standalone and lg_node drivers is documented as unreachable in production, because a fresh driver is built per request. It is kept as a safe default rather than removed, and tests now pin that shape so it cannot be reshaped silently.
- **`sqlc` headers on the store queries** — `internal/store/queries/audit.sql.go` and `user.sql.go` both carried a `Code generated by sqlc; DO NOT EDIT` header, but neither has a `.sql` query source: `sqlc.yaml` points its query input at `internal/store/sql/`, which holds only `schema.sql`. The false header invited someone to add a query file and run `make generate` — at which point sqlc would have overwritten the audit query with static SQL and silently dropped its date-range filtering. Both files now state that they are hand-maintained, and why. `audit.sql.go` cannot be regenerated at all, because its WHERE clause is built dynamically and sqlc cannot express that; `user.sql.go` is static and could be regenerated if a query source were ever added. The other five `.sql.go` files in that package already carried no such header.
