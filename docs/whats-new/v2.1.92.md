# HopStat v2.1.92

Saving a BGP neighbour no longer drops the session it describes.

## Fixes

- **Every save rebuilt the peer** — updating a neighbour removed it from the router and added it back, whatever had changed. Correcting a default-route AS, or moving a neighbour to another node, therefore tore down an established peering and left the session flapping while it rebuilt. A save is now compared against the running session first: when the peer address, bind address, remote AS and multihop setting are all unchanged, the record is updated in place and the session is left up. A change the router would actually see still rebuilds the peer, as before.
