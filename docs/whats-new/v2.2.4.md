# HopStat v2.2.4

The audit log is trimmed automatically. Until now it never was.

## Audit log retention

`audit.retention_days` has been in the generated config since the beginning, defaulting to 90, and nothing read it. The query that deletes old entries existed too, and nothing called it — so on any deployment that has been running a while the audit table only ever grew, and on a busy looking glass it is the table that grows fastest.

- **Old entries are now deleted.** A background pass runs at startup and every six hours, removing entries older than the retention window. The column it filters on is already indexed, so the delete stays cheap.
- **Retention is set in Admin → Settings**, in days, and is read on every pass — so shortening it takes effect at the next pass rather than the next restart. Your existing `audit.retention_days` seeds it on first run.
- **Zero means keep everything.** It has to be typed deliberately, and the field says what it costs. A negative or absurd value is refused when saving rather than being stored and ignored.

If you have been running HopStat for a long time, the first pass after upgrading will delete everything older than your retention setting. That is the point — but it is worth knowing before you restart, and the number removed is written to the log.
