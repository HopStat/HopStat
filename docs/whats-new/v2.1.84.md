# HopStat v2.1.84

The route marked active is now the one the router actually uses, and copying a result moved to the result itself.

## Fixes

- **Active path selection was arbitrary** — when a node held more than one path for a prefix, HopStat marked whichever the routing table happened to return first. That path was then starred in the results table and drawn solid on the network map, while the router's real choice appeared as a backup. Selection now follows the BGP decision process — local preference, AS path length, origin, MED, then the established path and a stable neighbour comparison — so it matches what `show route` reports. A router's own active-path marker still wins over anything HopStat reconstructs.
- **The table's bottom edge vanished under the cursor** — a hovered row was stacked above the frame's border and painted over it.

## Improvements

- **Copy sits with the result** — "Copy result" moved from the summary bar to the bottom edge of the results table, and clicking the result itself copies it too, with the same acknowledgement. Selecting text no longer triggers a copy, and the cursor no longer suggests the data cannot be selected. The summary bar keeps "Copy link".
- **Ping and traceroute copy the full report** — the output panel's existing copy button now yields the same report as the table (command, target, node, output and the link) instead of the bare output lines.
- **Recent queries on the home page** — previous queries appear as compact cards beside the quick-start ones, four to a row since they carry no description. The same question asked from several nodes is listed once, keeping the most recent run.
