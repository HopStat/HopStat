# HopStat v2.2.5

Fix iBGP session flaps when your router dials HopStat on TCP/179.

## Fixes

- **Dual-active TCP caused Broken pipe flaps** — HopStat always dialed outbound while the router also connected in, so established sessions dropped with `TransportError` / `Broken pipe` on the router side (often dozens of flaps overnight). iBGP neighbors now default to **passive mode**: HopStat listens and waits for the peer to connect instead of dialing both ways.
- **Existing iBGP neighbors pick up passive on upgrade** — the database migration sets passive mode for internal (same-AS) neighbors automatically. Restart HopStat after upgrading so sessions reload with the new setting.

## What's New

- **Passive mode on Admin → BGP Neighbors** — toggle per neighbor when you need HopStat to dial out (typical eBGP) or to wait for the router (typical iBGP). Session logs show `mode=passive` or `mode=outbound`.

## Notes

- After upgrading, restart HopStat once. Confirm the router flap counter stops increasing (`show bgp neighbor … | match Flap` on Juniper).
- eBGP neighbors stay outbound by default; only iBGP neighbors are switched to passive automatically.
