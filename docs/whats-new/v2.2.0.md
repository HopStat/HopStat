# HopStat v2.2.0

A new look, and a brand colour you can pick freely without breaking the interface.

## The redesign

- **A modern, quieter interface.** New typography — Manrope for the interface, JetBrains Mono for output and addresses — a single spacing and corner scale, and one elevation scale instead of shadows chosen per component. Light and dark were designed together rather than one derived from the other.
- **Your brand colour is used exactly as you enter it.** It is never lightened, darkened or shifted to make text fit. What adapts is everything derived from it.

## Fixes

- **Buttons and their labels were unreadable for some brand colours.** Picking a pale colour such as `#e0edd4` left text you could not read. Every derived colour — button labels, links, rings, borders, terminal output — is now measured against the surface it will sit on and solved until it clears the WCAG minimum, rather than being placed at a fixed lightness. A fixed lightness reads well for one hue and fails for another, because at the same lightness a yellow carries far more light than a blue.
- **Secondary text on the brand-tinted header and sidebar.** Those surfaces mix your brand into the card, so a dark brand darkened them well past the plain card and the muted labels on them fell to 3.7:1. Secondary text is now solved against the full range of tints the interface can paint, not just the plain surfaces.
- **Old databases with an out-of-range BGP port or AS number.** A port above 65535 or an AS number above the 32-bit range was silently wrapped into a different value while migrating. Both are now rejected as unset instead.

## Under the hood

Four gates now have to pass before anything ships, and all four run in CI:

- **Contrast is measured in a real browser.** Every page, in both themes, across a range of brand colours: each run of text on the rendered page is read back with its actual painted colours and checked against its WCAG threshold. The scanner is itself tested against text planted to fail, so a scan that quietly stopped measuring cannot report a clean page.
- **Smoke tests drive the compiled binary.** Bootstrap, server start, login and session, node management, and a full query through to its stored result — against the real server, not a mock.
- **Lint runs on everything.** The frontend linter had never run in CI and the strict Go configuration only ran locally; 109 Go findings and 33 frontend findings had accumulated behind them. Both are now clean and enforced.
- **Tests run in random order.** Four tests passed only because of the order they happened to run in: three assumed a process-wide cache was in the state some earlier test had left it, and one restored a stubbed function by rebuilding it instead of putting the original back, which made coverage itself order-dependent. All four are fixed, and the shuffle would catch the next one.
