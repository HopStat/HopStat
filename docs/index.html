Running in under a minute.

Download the binary and run it. The config file, its secrets and the first admin account are generated on first start.

The generated config.yaml

Everything you might change while it runs — site name and colour, AS number, footer links, MaxMind account, Cloudflare Turnstile, query timeout, audit retention, self-update — lives in Admin → Settings and applies without a restart.

Lost the admin password?

There is no self-service reset — no e-mail flow, no reset link. While you can still sign in, change it in Admin → Settings → Account. If you are locked out, re-run --bootstrap with LG_FORCE_ADMIN_PASSWORD=1 to overwrite the password in the database.

bash
sudo systemctl stop hopstat

sudo env LG_ADMIN_PASSWORD='new-password' \
         LG_FORCE_ADMIN_PASSWORD=1 \
         /usr/local/bin/hopstat --bootstrap --config=/etc/hopstat/config.yaml

sudo systemctl start hopstat

# Docker — pass both with -e, .env alone is not enough:
#   docker compose run --rm \
#     -e LG_ADMIN_PASSWORD='new-password' \
#     -e LG_FORCE_ADMIN_PASSWORD=1 \
#     hopstat --bootstrap --config=/data/config.yaml
  • The output must contain admin password set from LG_ADMIN_PASSWORD. admin password already configured means the force flag never reached the process.
  • sudo strips the environment, so sudo env VAR=… is required. With Compose use -e: only variables listed in the service's environment: block are forwarded from .env.
  • Without the force flag, LG_ADMIN_PASSWORD only seeds an account that never had a password.
  • Remove LG_FORCE_ADMIN_PASSWORD afterwards, or every restart overwrites the password you set in the panel.
  • Recovery targets admin@hopstat.local. If you changed the admin e-mail, the reset fails with no admin user found.

What is HopStat?

HopStat is a network looking glass for operators, ISPs and anyone who needs to see routing and reachability from more than one place. It replaces scattered SSH sessions and per-router CLI access with one web interface and REST API.

It ships as a single Go binary with the React interface, SQLite database, schema migrations and static assets embedded. No Node.js, no PostgreSQL, no separate web server.

Server mode runs queries across every node you add — routers reached over SSH or Telnet, agents at remote POPs, or standalone nodes on the server itself. An embedded GoBGP peer gives live access to the BGP table. Router credentials are encrypted at rest with AES-256-GCM, and ping and traceroute stream line by line as they run.

Two modes, one binary.

Run a central server that talks to routers directly, place agents at remote POPs, or both. The same binary switches mode with one flag.

--mode=server

Server

Query orchestration and the web interface

Serves the API and interface, runs the query engine and BGP sessions, and reaches routers over SSH or Telnet or hands queries to agents. Rate limiting, authentication, audit and GeoIP happen here.

  • Standalone nodes on the same host through the embedded /agent/v1 API
  • Embedded GoBGP peer with ADD-PATH receive and passive sessions
  • TLS from a certificate file or automatic Let's Encrypt
  • Cloudflare-aware client IP and optional Turnstile
--mode=agent

Agent

A lightweight node at a remote POP

A small REST server that runs queries where it stands. No database, no interface, no BGP manager. The server makes every request, so the agent needs no exposure to users.

  • Bearer-token authenticated API on :9090
  • Streaming endpoints for live ping and traceroute
  • Works behind NAT — the server calls the agent
  • systemd, Docker or bare metal

Every path per prefix, with BGP ADD-PATH.

BGP normally keeps only the best path for each prefix. To show every path your routers send — other next-hops, AS paths and communities — both HopStat and the peer must negotiate ADD-PATH (RFC 7911).

HopStat

On by default

  • bgp.add_path_receive: true in config.yaml
  • Negotiated on every IPv4 and IPv6 unicast neighbor
  • Neighbors live in Admin → BGP Neighbors, each with a default-route AS for prefixes missing from the table
  • Restart the neighbor after changing it, so the capability is advertised in OPEN
Sessions

Passive or outbound

  • Passive — HopStat listens and the router connects. The default for iBGP, where both sides dialling caused flapping sessions
  • Outbound — HopStat dials the router, the usual choice for eBGP
  • The session log says mode=passive or mode=outbound, and why a session went down

Peer router configuration

HopStat only receives additional paths; your router has to send them. Adjust AS numbers, neighbor addresses and policy names to your network.

Cisco IOS / IOS-XE

ios-xe.conf
! Under the BGP process — replace AS and neighbor IP
router bgp 65001
 neighbor 10.0.0.2 remote-as 65000
 neighbor 10.0.0.2 update-source Loopback0
 !
 address-family ipv4 unicast
  neighbor 10.0.0.2 activate
  neighbor 10.0.0.2 additional-paths receive
  neighbor 10.0.0.2 additional-paths send
  ! Export more than best-path — example policy:
  neighbor 10.0.0.2 additional-paths selection route-map EXPORT-ALL
 exit-address-family

Cisco IOS-XR

ios-xr.conf
router bgp 65001
 neighbor 10.0.0.2
  remote-as 65000
  address-family ipv4 unicast
   additional-paths receive
   additional-paths send
   ! Optional: advertise best + backup paths
   additional-paths selection route-policy EXPORT-ALL

Juniper JunOS

junos.conf
set protocols bgp group HOPSTAT type external
set protocols bgp group HOPSTAT neighbor 10.0.0.2 peer-as 65000
set protocols bgp group HOPSTAT family inet unicast add-path receive
set protocols bgp group HOPSTAT family inet unicast add-path send multipath
# For IPv6:
set protocols bgp group HOPSTAT family inet6 unicast add-path receive
set protocols bgp group HOPSTAT family inet6 unicast add-path send multipath

MikroTik RouterOS v7

routeros.rsc
/routing/bgp/connection
add name=hopstat remote.address=10.0.0.2 .as=65000 \
    local.role=ebgp add-path=both \
    address-families=ip,ipv6

BIRD 2.x

bird.conf
protocol bgp hopstat {
  local 10.0.0.1 as 65001;
  neighbor 10.0.0.2 as 65000;
  ipv4 {
    import all;
    export all;
    add paths on;
  };
}

Verify

  • On the peer, confirm the ADD-PATH capability in show bgp neighbors (Cisco) or show bgp neighbor (JunOS)
  • In HopStat the neighbor should be established; restart the session after enabling ADD-PATH on either side
  • Run a BGP query for a prefix with several upstream paths — the best path is starred and the others are listed with it
  • If only one path appears, the peer is still sending best-path only: check its export policy

A communities catalogue your peers can read.

Document the BGP community strings you use. HopStat matches them on every route lookup and publishes them on a public page linked from the site footer. The label stays Communities in every language.

Admin → Communities

Define the rules

  • Community — the exact string to match, e.g. 9121:65000
  • Description — shown on hover and on the public page
  • Severity — info, success, warning or reject
  • Scope — all nodes by default; per-node scope through the API
  • Active — switch a rule off without deleting it
Results

See them on every lookup

  • Matches appear as severity-coloured badges in the Communities column
  • Unmatched strings still show, only without a label
  • With ADD-PATH, each path's communities are matched on their own
  • /communities lists every active rule without signing in
